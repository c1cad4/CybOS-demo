# Зашифрованная база CybOS

После входа в CybWallet приложение открывает SQLCipher-базу `cybos-encrypted.db`. Ключ выводится из случайного секрета профиля с отдельным назначением; он не записывается рядом с базой. Восстановление пароля через те же 24 слова сохраняет ключ данных.

## Переход со старой версии

1. Закройте старые версии CybOS и сделайте резервную копию всей папки данных.
2. Войдите в профиль новой версии. При первом входе приложение копирует согласованный снимок `cybos.db`, включая доступные данные WAL, в зашифрованный временный файл.
3. После проверки целостности копия публикуется как `cybos-encrypted.db`. Старая база сохраняется. Последующие запуски используют только зашифрованную базу.
4. Проверьте чаты, память и настройки. Не запускайте старую версию для работы с этими данными: её изменения в старой базе автоматически не объединяются с новой.

Старый `cybos.db` и его журналы остаются открытой резервной копией. Этот этап не удаляет их автоматически. Храните резервные копии в защищённом месте. Удаление обычного файла не гарантирует стирание с SSD.

## Восстановление и ограничения

Храните вместе резервную копию зашифрованной базы и `profile-vault.json`. Сохраните 24 слова отдельно. Фраза восстанавливает доступ к ключу, но не возвращает потерянные файлы. Существующая база с неправильным ключом или повреждениями блокирует вход; открытого fallback и автоматического сброса нет.

Защищены страницы основной базы и её WAL: чаты, память и другие записи этого хранилища. Медиа, скачанные файлы, отдельные базы сторонних процессов и старые резервные копии этим изменением не зашифрованы. ОС хозяина всё ещё имеет доступ к процессу и экрану. Автоблокировка пока не реализована.

Публикация временного файла требует файловой системы с поддержкой hard link; FAT/exFAT для этого этапа не подходят. Unix-файл создаётся с правами 0600; отдельная настройка Windows ACL ещё нужна.

## Проверка

На macOS ARM64: 104 теста прошли, 4 пропущены; debug-сборка успешна. Проверены перенос FTS5 и user_version, снимок из WAL, отсутствие контрольного текста в зашифрованном WAL, отказ с неверным ключом, сохранение повреждённого файла и стабильность ключа после восстановления пароля. Windows и Intel macOS в этом этапе не проверены.
