# Вложения CybChat: первый этап

Прямая переписка с доверенным другом поддерживает бинарные файлы до 8 КиБ. Они передаются внутри существующего сообщения Noise; лимит кадра не изменён. Групповая отправка файлов пока не подключена.

1. Сохраните небольшой файл в CybWallet → Защищённые файлы.
2. Откройте личный чат с другом, сверьте и подтвердите его код безопасности.
3. Разверните «Защищённый файл · до 8 КиБ», выберите файл и нажмите «Отправить файл».
4. Получатель увидит имя и размер. Кнопка «Сохранить защищённую копию» добавит его в зашифрованное хранилище. В CybWallet нажмите «Обновить список», затем при необходимости выгрузите файл.

Файлы автоматически не открываются и не записываются в указанное отправителем место. Имена с разделителями пути и управляющими символами запрещены. Перед сохранением входящего сообщения проверяются версия формата, UUID, размер, Base64 и SHA-256. Noise и проверенные ключи обеспечивают защиту канала; SHA-256 здесь проверяет целостность содержимого и не заменяет аутентификацию.

Содержимое вложения хранится в зашифрованной истории чата уже до подтверждения доставки. Создание отдельной защищённой копии выполняется по кнопке, с квотой хранилища; повторное нажатие создаёт ещё одну копию. Пакет вложения не добавляется в граф знаний как пользовательский текст. Экспортированная копия и исходный файл остаются незашифрованными.

Оба участника должны использовать версию с поддержкой вложений. Старые версии могут показать сырой пакет как текст. Для файлов до 32 МиБ добавлена отдельная передача по частям с прогрессом, паузой и продолжением (см. CYBCHAT_FILE_TRANSFER_RU.md). У старого однопакетного способа из этого документа нет возобновления. Отложенной доставки и автоматической миграции прежних вложений пока нет. Увеличение размеров требует отдельного протокола потоковой передачи с ограничением памяти и диска, проверкой каждой части, отменой и возобновлением. Ограничение 8 КиБ относится к текущему этапу, а не к будущей цели обмена файлами.

На macOS ARM64 прошли 109 тестов, 4 пропущены; debug-сборка успешна. Новый loopback-тест использует Noise, сохраняет сообщение до ACK, проверяет бинарное содержимое максимального размера, replay-отказ и отклонение поддельного пути без записи в историю. Тесты формата проверяют повреждение содержимого, размер и версию. На двух физических устройствах и вручную через интерфейс этот этап ещё не проверен.
